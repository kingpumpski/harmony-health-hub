# Migration collision review: 20261002130000 and 20261002132500

Updated: 2026-11-25

## Scope and disposition

Compared four same-version migration candidates with the canonical hosted PostgreSQL catalog. Inspection was read-only; no clinical or inventory row contents were read.

Candidates:
- `20261002130000_pharmacy_global_catalogue_facility_stock_and_safety.sql`
- `20261002130000_scope_appointment_workflows_to_active_facility.sql`
- `20261002132500_patient_hub_read_rpc_get_compatibility.sql`
- `20261002132500_pharmacy_global_category_edit.sql`

Do not select a single winner for either duplicate version and do not replay these files unchanged. The live schema represents important portions of both tracks, but it has evolved and at least one residual authorization issue remains.

## 1. Appointment facility-scoping candidate is represented live

The canonical database contains:
- `get_appointment_worklist(integer)` and `get_appointment_schedulable_patients(integer)` as STABLE SECURITY DEFINER, empty search_path, authenticated EXECUTE only.
- Both read RPCs require a non-null active facility.
- Worklist filters both appointment and patient facility IDs to the active facility.
- Schedulable-patient list filters patient facility to the active facility.
- Both `create_appointment_workflow` overloads exist, SECURITY DEFINER with empty search_path and authenticated EXECUTE only; their inspected definitions enforce active facility and patient-facility alignment.

The live signatures are:
- `create_appointment_workflow(uuid,timestamptz,text,text)`
- `create_appointment_workflow(uuid,timestamptz,text,text,text,uuid)`

The candidate is substantially represented. Preserve both overloads and their current facility checks. Appointment scheduling overlap/capacity remains a separate concurrency/control gap from tenant isolation.

## 3. Pharmacy global catalogue and facility stock

The live schema contains `medication_catalogue`, facility-attributed `pharmacy_inventory`, dispensing plans and POS sales, with RLS enabled. The live `get_pharmacy_workspace(integer)` is STABLE SECURITY DEFINER, empty search_path, authenticated executable, anon denied. The candidate's global catalogue/facility stock model is therefore represented, but this review does not certify every table constraint, data backfill, or RPC body as identical to the candidate.

A residual facility-boundary issue exists in the live workspace RPC:
- Patient rows are filtered with `(v_admin OR (v_facility IS NOT NULL AND p.facility_id = v_facility))`.
- Prescription rows use the same admin bypass.
- Dispensing-plan rows use `(v_admin OR (v_facility IS NOT NULL AND d.facility_id = v_facility))`.
- Thus a user with the ordinary `admin` role can receive cross-facility patient, prescription and dispensing-plan data without selecting a facility. This is a SECURITY DEFINER query, so underlying RLS does not narrow those result sets.
- Inventory and POS sales are facility-equality filtered; unassigned inventory is exposed only in a separate admin/system-superuser section.

**Forward repair required:** distinguish facility-scoped facility admins from explicitly authorized platform operators. Ordinary facility admins should require a non-null active facility and receive only matching-facility patients, prescriptions and plans. Any platform-wide support role must be explicit, separately authorized, audited, and limited to the minimum data needed. Do not assume `admin` means global. Preserve catalogue visibility as the intentionally global, non-patient-identifying part of the workspace.
